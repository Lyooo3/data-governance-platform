# 数据库只读采集与本地原始库 Implementation Plan

**Goal:** 在数据库接入页批量采集PostgreSQL业务表，保存不可修改的本地原始库，再从原始库创建治理数据集并追溯来源。

**Architecture:** 保留现有Vue 3与FastAPI单实例，平台SQLite升级为结构版本3。每个采集批次产生独立SQLite原始库文件；分批读取远程表，共用REPEATABLE READ只读事务，成功后原子发布，失败或取消不提供不完整快照。密码仅存在本次请求/采集进程内存，不落盘。

**Tech Stack:** Vue 3 / FastAPI / sqlite3 / psycopg 3 / threading。

## 决策与边界

- 用户要求直接接入、批量复制本地再治理，保留对远程服务器只读的原约束。不开SSH，不改远程文件、表、账号或数据。
- 选择独立SQLite逻辑快照。备选pg_dump要求额外工具与本地PostgreSQL恢复环境；直接远程治理重复依赖线上库。当前快照保留表结构/主键及原值的PostgreSQL文本表示，非PostgreSQL物理备份，不复制索引执行结构、触发器、权限或程序。
- 仅采集当前账号可SELECT的非系统普通表和分区根表，不执行用户SQL，不采集视图/外部表，不静默跳过失败表。全选业务表支持一次采集；表清单可筛选和多选。
- 全库采集不限于治理引擎的10000行。采集上限独立为2GiB原始记录文本，超限整批失败，避免假称全量；治理副本每批仍限10000行，可明确选择字段及行区间，UI显示是否全表及已选范围。
- 原始快照不提供编辑/覆盖入口；再次采集产生新版本。采集支持进度、取消、失败详情和重启中断恢复。
- 数据源参数不含密码，读取/预览远程表需管理员并重新输入密码；完成后本地浏览和治理不再需要远程密码或连接。
- 平台新增raw_snapshots/raw_snapshot_tables/raw_dataset_links三表，原始库文件在.data-v3/raw下；来源通过外键及元数据追踪至治理副本。
- 不扩展现有单表线性治理为任意跨表SQL。本轮完成批量采集与单表治理入口，保留将来按需扩展多表关联的空间。

## 步骤与验收

1. 新增只读PostgreSQL连接器：连接测试、表/列/主键元数据、服务端游标，标识符转义，连接/查询超时，密码脱敏。安装官方psycopg依赖。
2. 新增结构版本3与原始库管理器：后台采集、分批写本地文件、原子成功发布、取消/重启中断、不可变快照分页与治理副本。
3. 接入认证API并更新健康检查、数据源表单及来源血缘。保护已有数据及外键。
4. 用专门Vue页面替换接入草稿：保存参数、测试/扫描、批量选择、采集进度、本地原始库、字段/记录预览、创建治理副本和跳转。
5. 隔离测试验证只读选项、SQL转义、快照一致性、失败/取消不发布、重启、全量超过10000行、字段类型转换、溯源及权限。完整构建与回归。
6. 使用用户给出的数据库进行真实只读表清单及批量采集，界面核验原始库和创建一个训练/考试数据治理流程。真实数据不写测试报告，不打印个人记录/密码。
7. 更新README/API/数据库设计与操作指南，记录真实表数/行数及剩余边界，保留服务运行。

## 完成记录

已完成全部步骤。真实PostgreSQL 15.17只读采集238张业务表、96,739行；原始文件125,845,504字节；下载文件摘要一致。276行考试副本在浏览器完成4规则治理、输出276、问题0。自动清洗字段预填缺陷已修复并实跑复测。56项隔离测试、生产构建及数据库检查通过；重启后59页面加载和原始库离线读取通过；平台与原始库联合备份已生成。原有业务记录对照备份保留，新接入真实数据保留供用户使用。
