# 本地治理模块补齐 Implementation Plan

**Goal:** 将21个未实现入口替换为可操作、可持久化、可验收的本地治理功能，完成删除与浏览器验收。

**Architecture:** 保持 Vue 3 + FastAPI 单进程架构。新增独立 SQLite 业务表及版本2迁移，分析引擎和本地后台调度单独成模块。审核、应用授权和事件投递具有真实状态及审计；视图使用声明式字段和过滤条件，不执行输入SQL，不调用任何外部服务器。

**Tech Stack:** Vue 3 / TypeScript / FastAPI / sqlite3 / asyncio / Decimal。

## 范围与决策（ADR）

- 用户已选择本地数据治理，不连接外部数据库，并明确允许删除本轮验收测试记录。
- 复用共享表单组件，按业务功能使用不同字段、动作和结果；保留原页面风格及路径。
- 原资源模型维持兼容；扩展业务采用独立固定表映射和外键，不依赖可注入的SQL表名。
- 对标、时效、关系和资金分析保存输入配置、真实统计与明细；数据处理只生成新数据集。
- 审核为本地管理员单级审核，保留对象快照，拒绝审批已变更的版本。
- 应用授权按应用与服务范围生效，密钥仅保存哈希；停用/撤销后即时拒绝查询。
- 视图服务是本地数据的字段投影与条件查询；外部接口入口实现本地接口适配与接收，不建立出站连接。
- 订阅比较真实快照产生增删改事件；推送实现SQLite收件箱的实际投递，不宣称发送到外部通知通道。
- 后台任务只在平台启动期间运行，关闭后暂停；重启读取持久化状态，错过周期合并一次执行。
- 单进程调度、10000行上限和角色权限保持明确，失败记录保留并可重试。

## 实现步骤

1. 删除引用保护与实际删除验收，保存备份及结果。
2. 新增版本2表及仓储方法：对标报告、审批、计划、视图、应用、授权、接口适配、订阅、变化事件、投递、收件箱。
3. 分离本地分析、视图计算、审批授权、调度与订阅模块，接入FastAPI生命周期。
4. 新增业务API并集成已发布服务的视图及应用授权查询。
5. 将21个入口登记为业务页面，新增分析、审核、调度、图谱、服务和消息页面；修正旧说明。
6. 补充隔离回归：真实对标结果、审批版本检查、按时执行、授权撤销、快照变化和幂等投递、角色和非法输入。
7. 构建重启，真实浏览器逐页新增、编辑、执行、查看、状态变化和删除验收。
8. 核对原数据，清理测试记录，更新数据库设计、API、README和最终验收报告。
