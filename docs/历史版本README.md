# 数据治理平台：前端与真实后端

默认启动真实业务后端。原平台编译资源用于门户及已有页面；数据库接入、画布流程及完整执行结果通过新增治理工作台操作。

## 快速启动

环境：Node.js **22.14及以上**。首次执行 `npm install`，已有依赖时直接双击 `启动项目.cmd`，或在本目录执行 `npm start`。

停止服务可双击 `停止项目.cmd`；关闭自动登录的模式可在启动终端按Ctrl+C。

- 工作台：http://127.0.0.1:4173/workbench
- 原平台首页：http://127.0.0.1:4173/home
- 后端健康检查：http://127.0.0.1:4173/api/health

平台配置使用SQLite，首次启动创建本地示例业务库。先在“治理流程”执行示例：8条输入、7条输出、2条问题记录、71.4%合格率。默认质量检查只报告问题，勾选“排除不合格记录”才会过滤数据。

## 接入MySQL

1. 工作台 → 数据库接入 → 添加数据库，填写名称、主机、端口、数据库名、用户名和密码。
2. 保存后点击“测试连接”，查看“表与字段”，或“同步元数据”。
3. 流程中的“读取数据”节点选择数据源和表；也可以配置单条只读SELECT查询。
4. 配置映射、清洗、过滤、去重及质量节点；点击节点“连出”和下一节点“连入”连接顺序。
5. 保存并执行，在“运行与报告”查看结果、下载CSV。

读取和检测可使用只读账号。另存MySQL结果时需启用“允许流程创建新的结果表”，使用有CREATE和INSERT权限的账号，并在输出节点填写**尚不存在的新表名**。

支持MySQL 8+、PostgreSQL和平台管理的SQLite。数据库口令使用AES-256-GCM加密保存，接口不返回口令，密钥保存在本机数据目录。连接和查询有超时。

## 已实现能力

| 能力 | 实现情况 |
| --- | --- |
| 持久化 | 配置、账号、会话、任务、结果、审计保存到SQLite，重启保留 |
| 数据库 | 连接检查、表字段、数据库内分页预览、元数据同步 |
| 拖拽流程 | 新建、添加及移动节点、连接、配置、保存、执行 |
| 治理节点 | 读取、映射、清洗、过滤、去重、质量检查、结果输出 |
| 质量规则 | 非空、唯一、正则格式、数值范围、允许值集合 |
| 运行管理 | 独立Worker执行、节点计数、失败、取消、超时及中断记录 |
| 数据维护 | 数据元、业务分类、限定词、代码集、目录、资产、规则、质量任务CRUD |
| 数据服务 | 发布、字段白名单、密钥授权、分页、每分钟60次调用限制、调用审计 |
| 权限 | 管理员/只读用户、密码登录、8小时会话、登录尝试限制 |
| 原页面适配 | 标准与目录列表、元数据、质量和运行统计等返回真实配置与结果 |

本版流程为**单数据源、线性执行**，每次最多10,000行、默认45秒，同时最多两个任务。超出上限明确失败，不把截断样本冒充完整检测。预览与发布查询在数据库内分页，不受执行行数限制。

输出新表推断基础数值或文本类型，不复制源表的索引、约束和外键。MySQL的DDL不能与平台结果记录共同提交：正常写入失败会回滚记录并清理本次创建的新表；强制停止或主机异常时可能留下空表，需检查后重新指定表名。所有输出不覆盖原表。

## 登录与环境配置

服务仅监听127.0.0.1，默认允许同源页面创建本机管理员会话，方便已有前端本地使用；该模式不用于公网部署。

如需密码登录，**首次初始化前**设置至少10位的 `ADMIN_PASSWORD`，同时设置 `LOCAL_AUTO_LOGIN=false`。已有账号不会因更改环境变量而重置密码。

已经初始化的工作空间，可先在“账号与审计”创建一个已知密码的新管理员，再关闭自动登录，并使用该账号登录。

可复制 `.env.example` 为 `.env`，填写配置，然后执行 `node --env-file=.env server.mjs`。普通 `npm start` 使用系统环境变量，不自动读取.env。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| PORT | 4173 | HTTP端口 |
| DATA_DIR | 项目下.data | 平台库、密钥及本地业务库 |
| BACKEND_MODE | live | replay为原录制回放 |
| LOCAL_AUTO_LOGIN | true | false关闭本机自动会话 |
| ADMIN_PASSWORD | 首次随机生成 | 使用密码模式时自行指定 |
| JOB_TIMEOUT_MS | 45000 | 可配置500至45000毫秒 |

备份需保留完整 `.data`，包括密钥；建议停止服务后再复制数据库，避免遗漏SQLite的WAL文件。连接配置不随源码公开。

## 录制回放及支持范围

`npm run start:replay`保留原回放模式：150条静态资源和586条接口响应。回放模式写操作不保存，与真实模式分开。

真实模式不会回放未实现业务的成功响应，未支持接口返回501。原厂审批、标准对标执行、Hive/Flink/YARN集群任务、实时流、关系和资金分析尚未实现。原编译包缺少部分入口及懒加载资源，不能保证所有原厂按钮可用；已实现业务通过工作台操作。

“数据接入”缺失入口现在连接工作台数据库接入，“系统设置”入口连接账号与审计。原始HAR未在当前目录，重建需另提供。`public/static/js`的另一套党建前端不参与本后端业务。

## 验证与代码

```sh
npm test
npm run validate
npm audit --omit=dev
```

测试使用隔离临时库，覆盖权限、CRUD、分页、真实读取、口令加密、治理结果、目标表不覆盖、取消超时、服务授权及重启持久化。MySQL/PostgreSQL驱动已实现，无用户连接信息时不声称真实环境联调完成。

- `server.mjs`：门户、真实API及可选回放。
- `backend/store.mjs`：持久化、账号、会话、密钥、结果、审计。
- `backend/connectors.mjs`：数据库连接、元数据、分页、新表输出。
- `backend/engine.mjs`、`job-worker.mjs`：流程校验与执行。
- `backend/service.mjs`、`legacy.mjs`：业务API、运行管理、原接口适配。
- `public/workbench/`：治理工作台。
- `docs/API.md`：接口及节点格式。
- `tests/backend.test.mjs`：自动验证。

驱动参考：[MySQL2官方文档](https://sidorares.github.io/node-mysql2/docs)、[node-postgres官方文档](https://node-postgres.com/features/queries)。
