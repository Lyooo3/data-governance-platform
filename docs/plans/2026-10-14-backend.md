# 数据治理后端 Implementation Plan

> 执行方式：在当前会话按步骤实现并验证；当前目录不是 Git 仓库，保留原始录制文件，不创建虚假的提交。

**Goal:** 为现有前端增加真实持久化、数据库接入、可视化流程执行、质量报告和数据服务能力。

**Architecture:** Node.js 单进程 HTTP 服务复用原页面；SQLite 保存平台配置、账号、会话、任务和结果。MySQL/PostgreSQL/SQLite 适配器读取用户配置的数据源；治理任务在独立 Worker 中执行，避免阻塞页面。原录制模式保留为显式可选模式，真实模式不回放业务成功响应。

**Tech Stack:** Node.js 22.14+、node:sqlite、mysql2、pg、原生 HTML/CSS/JavaScript 工作台。

## 架构决策

- ADR-001：采用模块化单体，直接复用现有启动入口。微服务会增加部署和联调成本，当前没有集群需求依据。
- ADR-002：平台数据库采用本地 SQLite，业务数据源支持 SQLite/MySQL/PostgreSQL；平台配置与业务数据分开。SQL 查询使用只读事务和超时；输出只创建新的目标表，不覆盖原表。
- ADR-003：原编译前端通过兼容接口访问真实标准和资产配置；缺失的数据接入入口连接到新的工作台。未实现的原厂接口明确返回不支持，不伪造业务执行成功。
- ADR-004：本地浏览器会话通过仅同源 POST 创建，接口校验会话与来源。另提供密码登录和管理员/只读权限；本机自动会话不用于公网部署。
- ADR-005：数据库口令加密保存；任务有记录、超时、取消、错误状态及审计。服务启动后把上次中断的任务标记为中断。

## 实现步骤与验证

1. 添加 `backend/store.mjs`：迁移建表、实体CRUD、分页、审计、密钥、会话；重开数据库验证持久化。
2. 添加 `backend/connectors.mjs`：三种数据源的连接检查、元数据、只读查询和新表写入；拒绝非法标识符与写SQL。
3. 添加 `backend/engine.mjs`、`backend/job-worker.mjs`：校验画布连线、运行映射/清洗/去重/质量/输出节点；验证有环、字段缺失、超时及失败状态。
4. 添加 `backend/service.mjs`、`backend/legacy.mjs`：真实REST API、身份与权限、旧页面接口适配、质量与运行统计、受控数据服务。
5. 修改 `server.mjs`：默认真实模式，保留 `--replay`；提供工作台资源和同源会话引导。
6. 添加工作台：数据源配置、表和字段、拖拽节点、节点参数、保存/执行、运行报告、标准与资产维护入口。
7. 添加自动测试：启动隔离环境，验证认证、权限、数据库连接、持久化CRUD、治理结果、分页、注入拒绝、服务调用和旧接口返回结构。
8. 浏览器联调并保存效果；更新一键启动、配置示例、接口及运行说明。

## 验收边界

必须完成一个本地真实数据库的治理闭环；MySQL/PostgreSQL驱动完成实现，无用户连接信息时不声称真实数据库联调成功。Hive/Flink/YARN集群任务、原厂审批引擎、关系与资金分析不在材料内，明确报告支持范围。现有截图与快照不自动导入账号、密码、数据源或业务数据。
