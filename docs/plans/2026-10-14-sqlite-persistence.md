# 治理平台SQLite持久化实施计划

**Goal:** 用户已选择本地独立SQLite，为已有可保存功能建表、迁移JSON并让接口使用数据库，交付真实README。

**Architecture:** 使用Python标准库sqlite3，单数据库、WAL、外键、事务及参数化查询。15类业务配置独立表，嵌套流程/代码项/规则关联/字段/数据行/报告拆分子表，账号/会话/预警/审计也入库。未知扩展字段用各实体的JSON扩展列兼容，不把整个系统序列化到一张表。

**Tech Stack:** 现有Vue 3 + FastAPI，SQLite3；不增加外部数据库服务。之前训练服务器禁止修改的要求继续有效，所有DDL仅在本机执行。

## 明确决定

- 数据库位置为GOV_DATA_DIR/platform.sqlite3，默认.data-v3/platform.sqlite3。
- 首次初始化先备份state.json，单事务导入配置、原ID、账号哈希、样例、结果、报告、预警及审计。成功才写迁移标记，失败回滚；后续不再读JSON，保留原文件。
- 空工作空间沿用已有样例种子；不生成审批/订阅等尚未实现业务的表或伪数据。
- 登录会话令牌仅保存哈希，8小时有效，迁移后的新会话可跨服务重启；旧内存会话需重新建立。密码哈希及发布密钥哈希原样迁移。
- 限流计数、登录尝试和运行中进程保持内存，不属于需要永久保存的业务内容；运行状态保存在数据库，重启标记中断。
- 对外已有JSON接口结构保持一致；health增加platformDatabase状态，databaseConfigured仍表示外部业务数据源未接入。
- 提供SQLite实际DDL和PostgreSQL建表参考，不连接或修改远程数据库；当前仓储仅支持SQLite。

## 实施顺序

1. 整理seed为独立函数，创建db/schema.sql及关系、索引和数据库版本表。
2. 实现事务仓储、子表保存/组装、会话、预警和审计方法；移除main/jobs对state字典和flush的操作。
3. 单事务首次迁移JSON，增加幂等状态和迁移数量校验，停止旧服务后本机初始化。
4. 添加数据库管理CLI：初始化、状态、完整性检查、SQLite备份；备份使用连接backup API，不只复制活跃WAL主文件。
5. 隔离测试所有原API与数据库、迁移幂等、子表更新/回滚、引用约束、重启、密码/密钥和会话持久化。
6. 更新环境页与README/API/数据库说明，构建、启动、页面验证，列出真实建表和迁移结果。

## 验收

- 所有业务保存通过SQL完成，不维护state内存镜像或每次重写JSON。
- 原数据迁移数量一致，运行8到7的报告可继续打开；训练数据库无写入。
- 数据库外键检查和完整性检查通过，重复初始化不重复导入或重置数据。
- 重启后规则、流程、结果、预警和会话保留；删除被引用资源失败并回滚。
- README写清平台数据库和外部业务数据库区别、实际文件路径、表清单、开发、建库、备份与恢复。
